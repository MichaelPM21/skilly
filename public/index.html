DOCUMENTACIÓN TÉCNICA

Qué es real en este proyecto y qué falta por conectar

Este proyecto corre sobre un backend Node/Express propio con base de datos SQLite real (server/skilly.db), persistente en disco. Reproduce el flujo completo: registro y validación de profesionales, marketplace, agendamiento sin doble reserva (verificado en el servidor), pago registrado y liquidación simulada autorizada por Skilly tras confirmar la entrega, y evaluaciones privadas que el servidor solo entrega a peticiones autenticadas de administrador.

✅ Real en este proyecto

  • Base de datos SQL real (SQLite) con tablas propias, ver server/db.js.
  • API REST propia (server/index.js), documentada en el README.
  • Privacidad de evaluaciones aplicada en el servidor: la ruta pública /api/professionals nunca incluye evaluaciones; solo /api/admin/evaluations las expone, y exige una sesión administrativa.
  • Agendamiento con verificación de disponibilidad y bloqueo de doble reserva en el servidor (no solo en el navegador).
  • Flujo de pago retenido → liberado.
Cuentas protegidas: contraseñas con hash, sesiones en servidor y permisos por rol. La identidad se revela únicamente al cliente después del pago confirmado.

💳 Pagos reales — Webpay Plus y PayPal

El checkout ahora se conecta con pasarelas de pago reales:

  • Webpay Plus (Transbank): integración real usando el SDK oficial, en el ambiente de integración/pruebas de Transbank (con credenciales públicas de prueba — no requiere configuración adicional para probarlo, pero tampoco cobra dinero real). Ver README para tarjetas de prueba y el paso a producción.
  • PayPal: integración real vía la API de Órdenes v2, en modo sandbox. Requiere que configures tu propia app gratuita de PayPal Developer en .env (PAYPAL_CLIENT_ID / PAYPAL_CLIENT_SECRET). PayPal no admite pesos chilenos, así que el monto se convierte a USD con una tasa configurable.
  • El comprobante ("cheque electrónico") que se genera tras el pago ahora incluye datos reales de la transacción: código de autorización, últimos 4 dígitos de la tarjeta (Webpay) o ID de captura (PayPal).

🔧 Simulado / pendiente de integración real

  • Boletas / facturas electrónicas: el comprobante descargable no es aún un documento tributario válido ante el SII. Se requiere un proveedor autorizado (ej. Haulmer/OpenFactura, Bsale).
  • Liquidación al profesional: se registra de forma simulada, con comisión y monto neto. No realiza transferencias bancarias.
  • Aviso por Gmail: el envío de correo funciona de verdad (Nodemailer + Gmail), pero requiere que configures tu propia cuenta de Gmail con una "contraseña de aplicación" en .env — sin eso, la solicitud se guarda igual pero no se envía el correo.
